# AI Assistance Disclosure

This project used AI assistance for implementation support. The assistance was limited to code scaffolding, debugging, documentation drafting, local data-quality checks, front-end performance improvements, and delivery-readiness review.

The analytical framing, selected track, data-source choices, weighting decisions, interpretation of limitations, and final responsibility for the submitted work remain with the student. No API keys or private credentials are included in this project.

## Assisted Areas

- Built and iterated the local Python pipeline for the 500 m grid, H3 r8 aggregation, scoring fields, and app-ready JSON payload.
- Helped inspect the 2024 classified POI archive and document category-mapping assumptions.
- Helped create documented notebooks aligned with the project brief.
- Helped build and test the local interactive web app, including mode toggles, layer toggles, hex details, recommender sliders, and data transparency.
- Helped identify and document methodological limitations, especially where the current prototype uses proxy accessibility rather than full routing-engine isochrones.

## Human Review Needed Before Submission

- Confirm that all data collection complies with source terms of service.
- Review and, if needed, adjust scoring weights to match the intended planning argument.
- Replace proxy transit and car surfaces with routing or GTFS-aware calculations if the final standard requires true four-mode isochrones.
- Create the GitHub repository, public deployment, and Trello board through the required external platforms.
